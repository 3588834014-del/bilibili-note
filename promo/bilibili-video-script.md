# B站视频脚本：bilibili-note

> 用途：B站发布用。目标时长 **4 分 30 秒**，删掉备注里标「可删」的行可压到 3 分半。
> 受众：看知识区视频、有整理笔记习惯（或想养成）的人。不面向开发者，所以不讲实现，只讲"它替我省了什么"。
> 本文里的所有数字都来自仓库 README.md 与 CHANGELOG.md 的实测记录，录制时不要改。
> 文中 `https://github.com/3588834014-del/bilibili-note` 是 GitHub 链接位，发布前统一替换。

---

## 1. 标题候选（5 个）

1. 两小时的 B站合集，变成一篇能跳着看的笔记
2. 只拉字幕不下载视频：B站链接一键进 Obsidian
3. B站视频转笔记，没字幕的它宁可跳过也不编
4. 别再边看边手抄了，让 B站链接自己变成笔记
5. 把 B站视频存进 Obsidian，硬盘里只多一个 .srt

> 选用建议：主推 2（差异化最直白）。1 适合做合集向的补充，3 适合吸引对"AI 乱编"反感的人。

## 2. 一句话价值主张

把一条 B站视频链接，变成 Obsidian 库里一条能跳转、能检索的结构化笔记——有摘要、有带时间戳跳转的核心要点、有折叠的完整字幕，全程**只拉字幕，不下载视频**。

## 4. 必须讲清的三个技术点（为什么值得）

录制前先过一遍这三条的"为什么"，口播可以即兴，但别讲错。

### 4.1 只拉字幕，不下载视频

- 脚本内部固化的字幕命令（SKILL.md 原话，不要改成别的）：

  ```bash
  yt-dlp --cookies <归一化cookie> --skip-download \
         --write-subs --write-auto-subs \
         --sub-langs ai-zh --sub-format srt/best \
         --paths <工作目录> -o "%(id)s" --no-warnings "<URL>"
  ```

- `--skip-download` 是硬要求：它让 yt-dlp 只写字幕文件。跑完确认工作目录里**没有** `.mp4/.flv/.m4a/.webm/.part`，出现即为失败信号。
- 现场验证方式：`ls` 工作目录，只应看到 `.srt` 与 `manifest.json`。
- 为什么值得：硬盘不涨、不用等下载、只处理文本；要转写才需要 ffmpeg/whisper，这个工具刻意不引入。
- 一句话口径："下载通道只有 yt-dlp，且只走字幕这一条路。"

### 4.2 多 P 合集自动拼接

- 实测：一条 **2:10:32 / 6 分 P** 的合集 → **2807 段 / 33214 字**，与独立拼接的结果逐段一致。
- 机制：逐分 P 抓字幕，按累计时长平移——`P1 段原时间戳 + 0`、`P2 段原时间戳 + P1 时长`、`P3 段 + P1 + P2 时长`，拼成一条连续时间轴。
- 要点跳链形态：`{合集URL}/?t={累计秒}s`。
- 某个分 P 没有字幕时跳过该分 P，但**保留它占用的时间**，时间轴不会错位。
- 默认行为，用户不需要为合集做任何额外操作；传 `?p=6` 则只取第 6 个分 P。
- 现场可讲的对照：你直接拿 yt-dlp 去下这个链接，只会得到第一个分 P。
- 抓取较慢：每个分 P 两次请求，2 小时合集约 2 分钟。

### 4.3 无字幕就跳过，不硬造

- 拿不到字幕 → **跳过该视频，不生成空笔记**，向用户报告原因。
- 报告要区分两种原因：**视频本身没字幕**（跳过）／ **cookie 登录态失效**（提示重新导出）。
- 不做语音转写——那是另一条工具链，本工具刻意不引入 ffmpeg/whisper 依赖。
- 为什么值得：不会有"看起来正常、其实内容是编的"笔记混进库里。这正好呼应标题候选 3。
- 另一个同类设计可以顺口提：合集里若两个分 P 的字幕正文完全相同，脚本会**报错拒绝生成**，拦的就是"每页都读到同一份字幕"这种外表正常的故障。

## 7. 置顶评论草稿

> 集中回答几个一定会被问的问题，装之前先看这条 👇

**Q：怎么装？**
A：`pipx install git+https://github.com/3588834014-del/bilibili-note.git`，装完就有 `bili-note` 命令。无第三方 Python 依赖，Python 3.8+ 只用标准库。如果你在用 DeepSeek Harness，它同时也是一个 skill，clone 下来复制到 `~/.agents/skills/` 就行；仓库里的 `python scripts/install.py` 可以代劳，加 `--dry-run` 先看会复制什么。

**Q：要不要登录？**
A：要。B站的 AI 字幕接口需要登录态，所以得导一次 cookie：浏览器装「Get cookies.txt LOCALLY」→ 登录 bilibili.com → Export，把 `cookies.txt` 放在当前工作目录，或用环境变量 `BILI_COOKIES` 指向它。只有 UP 主自己上传了字幕的视频才可以跳过这步。

**Q：我导出 cookie 之后直接 `--cookies` 给 yt-dlp，报 invalid Netscape format cookies file，怎么办？**
A：这是这个项目踩得最深的坑。该扩展导出的行是 `.bilibili.com ⇥ FALSE ⇥ / …`——domain 带前导点，第 2 列的 host-only 标志却是 FALSE，正好踩中 Python `http.cookiejar` 的断言 `domain_specified == initial_dot`，于是 yt-dlp 直接拒绝加载整个文件。更坑的是它的表象：字幕永远拿不到，看起来像"这个视频没有字幕"。脚本会先归一化（去前导点 + 置 FALSE）再喂给 yt-dlp，所以正常用不会遇到；但你手动调 yt-dlp 时会撞上。

**Q：会下载视频吗？占硬盘吗？**
A：不会。`--skip-download` 是写死的硬要求，跑完工作目录里应该只有 `.srt` 和 `manifest.json`；出现 `.mp4/.flv/.m4a/.webm/.part` 就是失败信号。

**Q：支持油管或其他网站吗？**
A：只支持 B站。yt-dlp 能下的其他站点不在设计范围内。

**Q：视频没有字幕怎么办？**
A：跳过并告诉你原因（视频本身没字幕 / cookie 登录态失效），不会生成空笔记，也不做语音转写——那属于另一条工具链，这个项目刻意不引入 ffmpeg/whisper 依赖。

**Q：AI 字幕错字很多，笔记会跟着错吗？**
A：识别错误确实常见。处理边界是：引用原句就照抄识别结果，不"顺手改对"；能合理还原的按语义概括，不写成引号引语；完全不可解的丢掉不猜。字幕质量明显影响理解时会跟你说明。

**Q：两小时的长视频能用吗？**
A：能。合集是自动识别的，逐分 P 抓字幕再按累计时长平移成连续时间轴。实测 2:10:32 的 6 分 P 合集得到 2807 段 / 33214 字。抓取较慢，2 小时合集约 2 分钟。

**Q：为什么笔记里的要点行长得像坏掉的表格？**
A：故意的。要点行以 `|- ` 开头，下游归档管线的校验器只认这个形状，写成标准列表 `- [...]` 会被判「要点不足」。格式约定见仓库 `docs/FORMAT.md`。
